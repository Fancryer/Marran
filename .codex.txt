# Mårran Overview

Mårran is an experimental statically typed functional programming language focused on the interaction between:

- non-strict evaluation
- mutable bindings
- algebraic effects
- environment snapshot semantics
- Core semantic principles


## 1. Laziness

Evaluation is demand-driven. Expressions are not evaluated unless forced explicitly or required by semantics. `force` is an explicit operation affecting evaluation order.

## 2. Mutation model

Mutation affects bindings, not values. `var` introduces mutable bindings. `:=` rewrites bindings in the environment. Values themselves remain immutable. Mårran uses environment-based mutation semantics rather than a separate heap/store model.

## 3. `imm`

`imm` is a binding qualifier, not a function. An `imm` binding captures and freezes the surrounding environment at binding time. Subsequent mutations outside the snapshot do not affect evaluation inside the frozen environment. This acts as a mutation isolation boundary.

## 4. Effects

Effects are represented via row polymorphism.

Handlers are lexical and restricted:

- no explicit `perform`
- no freely manipulable continuations
- `resume` is constrained (effectively one-shot)

Some built-in effects affect semantics structurally:

- `Var`
- `Read`
- `Rebind`
- `Cell`

Effects are tracked explicitly in function types:

```marr
I -> {Effects} O
```

## 5. Blocks

Blocks are not expressions. A block is a separate semantic category:

`B ::= s1; ...; sn; e`

Functions abstract over blocks. The language is therefore closer to:

- a block-oriented functional language
than
- pure λ-calculus with statements

## 6. Type system

The type system distinguishes:

- meta variables
- skolem variables
- bound variables

Inference includes:

- occurs check
- row unification
- scope-sensitive instantiation

Implementation status

Implemented:

- lexer
- parser
- elaboration pipeline
- typed IR
- partial type inference
- interpreter core

Current focus:

- formal operational semantics
- typing rules
- denotational model
