## P0 — корректность

### P0-5. Операция эффекта видна только внутри `under ... to ... handle`

Объявление `effect` регистрирует операции в области видимости обработчика, а не
в той, где объявлен сам эффект, поэтому функцию, которая должна выполнять
эффект, нельзя ни написать, ни снабдить рядом:

```
effect Doubt
  ask : Int -> Int
end

funct twice () : {Doubt} Int = + (ask 1) (ask 2)   // E0007: `ask` is not in scope
funct twice () : Doubt Int   = + (ask 1) (ask 2)   // Unknown row alias: Doubt
funct twice () : {...Doubt} Int = ...              // Unknown row alias: Doubt
```

Работает только тело самого `under`. То есть эффект нельзя вынести в функцию, а
вся линия 0.2 — про эффекты. Пока это так, `row D = {...Doubt}` тоже не
разбирается: имя эффекта в позиции ряда считается алиасом ряда, а не эффектом.

Решение: операция эффекта видна там, где объявлен `effect` (её тип — как в
объявлении); имя эффекта допустимо в позиции ряда наравне с `row`-алиасом, в
том числе под `...`. `under` тогда только снимает обработчик, а не делает
операции видимыми впервые.

Готово, когда: все три формы — `{Doubt}`, `Doubt`, `{...Doubt}` — работают
одинаково, `row D = {...Doubt}` разбирается, а `twice` вызывается под
обработчиком без `force`-костылей.

### P0-4. `Nothing` — нижний тип, но унифицируется только слева

Пустой массив типизируется как `[Nothing]`. В `unifyTypes` ветка
`(TNothing, _) -> pure scope` срабатывает, только когда `Nothing` слева:

```
sayn [[], [1]]   // [[1], []]  — ok
sayn [[1], []]   // E0003: cannot unify the type `Int` with the type `Nothing`
```

Решение: `Nothing` — нижний тип. `Nothing <: T` для любого `T`, и, в частности,
`[Nothing] <: [T]` (массив ковариантен по элементу). Порядок элементов в
литерале не должен влиять на вывод; `f x`, где параметр объявлен `Nothing`,
по-прежнему не принимает `Int` — `Int` не подтип `Nothing`.

Готово, когда: `[[1], []]` и `[[], [1]]` типизируются одинаково, `[] : [Int]`
работает, а аннотация `Nothing` остаётся ненаселённой.

### P0-1. `#{ base | ... }` — это иммутабельное обновление записи

Конструкция разбирается, типизируется и выполняется, но поля base в результат
не попадают — ни в тип, ни в значение:

```
val base = #{ val a = 1; val b = 2 };
val s = #{ base | val c = 3 };
sayn s          // #{val c = 3}
sayn s@a        // E0015: this record has no field `a`
```

Причина: `inferRecord` для `Just anchor` складывает только новые поля
(`accProps`), а интерпретатор (`TERecord _ ps _`) игнорирует anchor и строит
окружение только из `ps`.

Решение: это не «расширение», а иммутабельное обновление записи, как в Haskell
и OCaml (`r { field = v }`): результат содержит все поля base, а перечисленные
поля заменены новыми значениями. Base не меняется. Мутабельность поля менять
нельзя — это уже диагностируется. `var`-поля в результате остаются `var`-полями
новой записи (новые ячейки, base не затронут).

Готово, когда: тип результата — base плюс/минус перечисленные поля; `s@a`
читает поле base; `sayn s` печатает все поля; изменение `s@b` не меняет `base`.

### P0-3. Встроенные функции строгие, хотя язык нестрогий

`if` ленив (`if true then sayn 1 else spin ()` печатает 1), а `and` — нет:

```
funct spin (n Int) : Int = spin n
sayn (and false (ieq (spin 1) 0))   // не завершается
```

`and` — нативное замыкание, которое сразу делает `getBool addrB`.

Решение: все встроенные функции нестрогие по аргументам, как и пользовательские
(аргумент приходит thunk-ом, форсируется только там, где значение нужно).
`and`/`or` замыкаются: `and false x` не трогает `x`, `or true x` не трогает `x`
(когда `or` появится). Для остальных нативных операций — ревизия: форсируется
ровно то, что нужно для результата.

Готово, когда: `and false (ieq (spin 1) 0)` печатает `false`; есть тест на
ленивость каждого логического встроенного.

### P0-2. Память не освобождается: рекурсия падает на куче

`sHeap :: IntMap Value` только растёт, сборки мусора нет, хвостовые вызовы не
оптимизируются. 100 000 итераций хвостового цикла — 4.6 ГБ аллокаций, 217 МиБ
максимальной резидентной памяти и 497 МиБ всего; на Windows это упирается в
`VirtualAlloc`.

```
funct loop (i Int) (acc Int) : Int =
  if ieq i 0 then acc else loop (- i 1) (+ acc 1)
// loop 1000000 0 -> ok; loop 2000000 0 -> getMBlocks: VirtualAlloc MEM_COMMIT failed
```

Сообщение об ошибке — из RTS GHC, без спана и кода `E____`.

Решение: трассирующий сборщик мусора над `sHeap`/`sEnvs` — корни в текущем
окружении, стеке продолжений, стеке обработчиков, снимках; недостижимые ячейки и
окружения освобождаются. Подсчёт ссылок не подходит: в языке возможны циклы
(запись, окружение которой ссылается на себя). Сборка должна быть безопасна
относительно ленивости: thunk держит окружение, поэтому окружение живёт, пока
жив thunk.

Готово, когда: живая память не растёт с числом итераций, а исчерпание памяти
сообщается диагностикой со спаном и кодом.

### P1-1, P1-2. Стандартная библиотека

Нужно потихоньку реализовать stdlib по сигнатурам из `app/std.marr`:
`Functions`, `Numbers`, `Strings`, `Booleans`, `Arrays`, `Pairs`, `Output`,

Как: каждое имя из рекорда получает схему в `Scope.globalScope` и значение в

Проверить первым делом: лексер сегодня, возможно, не разберёт `` `R ``, `+.`,
`*.`, `||`, `&&`, `^`, `<.` из `app/std.marr`.

Отдельно: дозавести встроенное (`String` нельзя ни склеить, ни сравнить; `Float`
нельзя сложить; нет `*`, `/`, `%`, `<=`, `>=`, `!=`).

### P1-3. Присваивание только имени

```
var r = #{ var a = 1 };
r@a := 2;          // E0013: unexpected `:=`
```

Решение: расширить statement-assignment до `path_exp := exp`, где
`path_exp: name (@path_exp)?`. Это же даёт `r@a := 2` и `r@a@b := 2`.

### P1-5. `match ... to ...`, `enum`, аннотации выражений

Грамматика `match` (ANTLR, от Алисы):

```
match_to: 'match' block 'to' match_clause+;

match_clause: ('|' pattern ('if' exp)? | primitive_clause ('as' Name)?) '=>' block;

primitive_clause: '|' (int+ | float+ | string+);

pattern:
  int                                               #int_pattern
  | float                                           #float_pattern
  | string                                          #raw_str_pattern
  | <assoc=left> left=pattern '<-|' right=pattern   #str_ends_with_pattern
  | <assoc=right> left=pattern '|->' right=pattern  #str_starts_with_pattern
  | nil                                             #nil_pattern
  | boolean                                         #boolean_pattern
  | Name                                            #name_pattern
  | 'val' (Name | path_exp)                         #val_pattern
  | arr_pattern                                     #array_pattern
  | <assoc=right> left=pattern ',' right=pattern    #tuple_pattern
  | '#' con_pattern                                 #constructor_pattern
  | pattern 'as' Name                               #alias_pattern
  | pattern ':' type                                #cast_pattern
  | '_'                                             #wildcard
  | '(' pattern ')'                                 #paren_pattern
  ;

con_pattern
  : Name          #singleton_constructor
  | Name nil      #empty_constructor
  | Name patterns #non_empty_constructor
  ;

arr_pattern
  : '[' ']'                                                 #empty_array
  | '[' head=pattern body=patterns? (';' tail=pattern)? ']' #non_empty_array
  ;

patterns: pattern+;
```

Алгебраические типы:

```
enum_def: 'enum' Name type_params? eff_params? enum_case+;
enum_case: '|' Name ('(' constant_qualifier? Name (':'? type)? ')')?;
```

Энум — несколько конструкторов, у каждого может быть квалификатор мутабельности;
без квалификатора — `val`:

```
enum Maybe[T] | None | Some (value `T)
```

Аннотации типов выражений — через двоеточие:

```
[1, 2, 3] : [Int]
```

### P1-6. Модули и `import`

```
module name [d1 ... dn]

import a                    //| whole module a
import a@i1                 //| (module a)@decl
import a [i1 ... in]        //| (module a)@i1 ... (module a)@in
import@native a             //| import whole native module a
import@native a@i1          //| ...
import@native a [i1 ... in] //| ...

d1
...
dn
```

`d1 ... dn` — список экспортируемых объявлений: функции, эффекты, энумы, алиасы
рядов и типов. Точки с запятой не нужны. Если два объявления носят одно имя, в
списке экспорта перед именем пишется вид: `funct/enum/type/effect/row/...`.
`i1 ... in` — импортируемые объявления другого модуля. Модули вычисляются
нестрого и поддерживают взаимно рекурсивные импорты.

## P2 — интерпретатор и инструменты

### P2-1. Конфигурация в `marr.av`

`Config.hs` нигде не используется: `app/Main.hs` его не импортирует, а конфиг
ищется как `marr.ilyn` / `~/.config/marr/marr.ilyn`. Решение: доработать
`Config.hs` так, чтобы конфигурация интерпретатора описывалась в `marr.av`, и
подключить загрузчик в `Main`.

### P2-2. Печать значений

Функции печатаются адресом (`!closure[&00000001]!`), thunk-ы — `!vthunk: ...!`,
`trace` показывает thunk, а не значение. Не критично, но улучшить.

### P2-3. Запуск по абсолютному пути

`--run` принимает только имя в `app/marr` (без пути и расширения):

```
marran-exe --run guess          // program not found: guess.marr
```

Решение: запускать интерпретатор на произвольном файле по пути (в том числе
абсолютному).

### P2-4. Нативные лямбды не нужны

`TENLambda` в интерпретаторе — `rtError "native lambdas are not implemented"`.
Решение: нативные лямбды не реализовывать; их значения инжектятся прямо в
нативный скоуп (самый глобальный, выше пользовательского глобального).

### P2-5. `read_string` требует кавычек

`read_string` парсит строку как литерал Mårran: `hello` — ошибка, `'hello'` —
нет. Для интерактивных программ это неожиданно. Решение: читать строку целиком,
без обязательных кавычек.

### P2-6. Предупреждения сборки

`stack build` даёт `-Wunused-top-binds`, `-Wunused-imports`, `-Wduplicate-exports`
и т.п. Часть почищена; остальное — по мере касания файлов.

### P2-7. `stack.yaml` — источник истины

Явный `hpack` не нужен. `stack.yaml` — источник истины; `Marran.cabal` не
поддерживать вручную ради расхождения с `package.yaml`.

## Бэклог

- **P1-4. Явное применение типов (`with`)** не работает нигде: `With` требует
  `TForall`, но `XVar` инстанцирует схему сразу, а лямбда `TForall` не
  производит, поэтому любое `with` даёт E0017. Слишком долго и сложно чинить
  сейчас.
  ```
  funct loop[T] (x T) : T = x
  sayn (loop with [Int] 5)      // E0017
  sayn (f with [`Int] 5)        // E0017
  ```
  Сопутствующее: возвращаемый тип с голой типовой переменной требует скобок
  (`: `A`), higher-rank параметр объявить можно, применить нельзя.
