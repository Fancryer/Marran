## P1 — язык

### P1-1, P1-2. Стандартная библиотека

Нужно потихоньку реализовать stdlib по сигнатурам из `app/std.marr`:
`Functions`, `Numbers`, `Strings`, `Booleans`, `Arrays`, `Pairs`, `Output`,
`Input`, `Conv`, эффекты `Env`, `File`, `Random`, `Time`, `System`, `Error`.

Как: каждое имя из рекорда получает схему в `Scope.globalScope` и значение в
`IntInterpreter.buildInitialEnv` (нативная операция) или в библиотеке на самом
Mårran. Ссылки на функции из рекордов продублировать в глобальной области, чтобы
не писать `Numbers@+`, `Numbers@to_float`. `Builtins.builtins` сверяет два
списка, поэтому имя, добавленное с одной стороны, диагностируется сразу.

Сделано: `Numbers`, `Strings`, `Booleans` — все имена, и напрямую, и через запись
(запись — вид на те же значения, а не копия). Лексер разбирает `+.`, `||`, `&&`,
`^`, `<.`. Нулевой делитель `/` — эффект `Error` (встроенный, с нижним
обработчиком → E0020), `%` и `%.` — чистая диагностика E0020.

Осталось: `Functions` (поля записей пока не полиморфны — `inferRecord`
выводит их мономорфно, это общее ограничение), `Arrays`, `Pairs`, `Output`,
`Input`, `Conv`, эффекты `Env`, `File`, `Random`, `Time`, `System`.


### P1-3. Присваивание только имени

```
var r = #{ var a = 1 };
r@a := 2;          // E0013: unexpected `:=`
```

Решение: расширить statement-assignment до `path_exp := exp`, где
`path_exp: name (@path_exp)?`. Это же даёт `r@a := 2` и `r@a@b := 2`.

### P1-5. `match ... to ...`, `enum`, аннотации выражений

Грамматика `match` (ANTLR, от Алисы):

```
match_to: 'match' block 'to' match_clause+;

match_clause: ('|' pattern ('if' exp)? | primitive_clause ('as' Name)?) '=>' block;

primitive_clause: '|' (int+ | float+ | string+);

pattern:
  int                                               #int_pattern
  | float                                           #float_pattern
  | string                                          #raw_str_pattern
  | <assoc=left> left=pattern '<-|' right=pattern   #str_ends_with_pattern
  | <assoc=right> left=pattern '|->' right=pattern  #str_starts_with_pattern
  | nil                                             #nil_pattern
  | boolean                                         #boolean_pattern
  | Name                                            #name_pattern
  | 'val' (Name | path_exp)                         #val_pattern
  | arr_pattern                                     #array_pattern
  | <assoc=right> left=pattern ',' right=pattern    #tuple_pattern
  | '#' con_pattern                                 #constructor_pattern
  | pattern 'as' Name                               #alias_pattern
  | pattern ':' type                                #cast_pattern
  | '_'                                             #wildcard
  | '(' pattern ')'                                 #paren_pattern
  ;

con_pattern
  : Name          #singleton_constructor
  | Name nil      #empty_constructor
  | Name patterns #non_empty_constructor
  ;

arr_pattern
  : '[' ']'                                                 #empty_array
  | '[' head=pattern body=patterns? (';' tail=pattern)? ']' #non_empty_array
  ;

patterns: pattern+;
```

Алгебраические типы:

```
enum_def: 'enum' Name type_params? eff_params? enum_case+;
enum_case: '|' Name ('(' constant_qualifier? Name (':'? type)? ')')?;
```

Энум — несколько конструкторов, у каждого может быть квалификатор мутабельности;
без квалификатора — `val`:

```
enum Maybe[T] | None | Some (value `T)
```

Аннотации типов выражений — через двоеточие:

```
[1, 2, 3] : [Int]
```

### P1-6. Модули и `import`

```
module name [d1 ... dn]

import a                    //| whole module a
import a@i1                 //| (module a)@decl
import a [i1 ... in]        //| (module a)@i1 ... (module a)@in
import@native a             //| import whole native module a
import@native a@i1          //| ...
import@native a [i1 ... in] //| ...

d1
...
dn
```

`d1 ... dn` — список экспортируемых объявлений: функции, эффекты, энумы, алиасы
рядов и типов. Точки с запятой не нужны. Если два объявления носят одно имя, в
списке экспорта перед именем пишется вид: `funct/enum/type/effect/row/...`.
`i1 ... in` — импортируемые объявления другого модуля. Модули вычисляются
нестрого и поддерживают взаимно рекурсивные импорты.

## P2 — интерпретатор и инструменты

### P2-1. Конфигурация в `marr.av`

`Config.hs` нигде не используется: `app/Main.hs` его не импортирует, а конфиг
ищется как `marr.ilyn` / `~/.config/marr/marr.ilyn`. Решение: доработать
`Config.hs` так, чтобы конфигурация интерпретатора описывалась в `marr.av`, и
подключить загрузчик в `Main`.

### P2-2. Печать значений

Функции печатаются адресом (`!closure[&00000001]!`), thunk-ы — `!vthunk: ...!`,
`trace` показывает thunk, а не значение. Не критично, но улучшить.

### P2-3. Запуск по абсолютному пути

`--run` принимает только имя в `app/marr` (без пути и расширения):

```
marran-exe --run guess          // program not found: guess.marr
```

Решение: запускать интерпретатор на произвольном файле по пути (в том числе
абсолютному).

### P2-4. Нативные лямбды не нужны

`TENLambda` в интерпретаторе — `rtError "native lambdas are not implemented"`.
Решение: нативные лямбды не реализовывать; их значения инжектятся прямо в
нативный скоуп (самый глобальный, выше пользовательского глобального).

### P2-5. `read_string` требует кавычек

`read_string` парсит строку как литерал Mårran: `hello` — ошибка, `'hello'` —
нет. Для интерактивных программ это неожиданно. Решение: читать строку целиком,
без обязательных кавычек.

### P2-6. Предупреждения сборки

`stack build` даёт `-Wunused-top-binds`, `-Wunused-imports`, `-Wduplicate-exports`
и т.п. Часть почищена; остальное — по мере касания файлов.

### P2-7. `stack.yaml` — источник истины

Явный `hpack` не нужен. `stack.yaml` — источник истины; `Marran.cabal` не
поддерживать вручную ради расхождения с `package.yaml`.

## Бэклог

- **Трамплин / дефункционализация.** Кучи больше нет (она в Haskell), но
  живая память всё ещё растёт с числом хвостовых вызовов: CPS-интерпретатор на
  `callCC` оставляет Haskell-кадр на каждый вызов, а в нём окружение вызова.
  Замер: `loop n 0` — ~300 Б на итерацию на одну переменную цикла, ~600 Б на
  две. Поэтому `+RTS -M64m` обрывает цикл на несколько сотен тысяч шагов, хотя
  без ограничения проходят десятки миллионов. Лечится только переводом
  `evalExpr`/`evalBlock`/применения функции на машину с явными продолжениями
  (заново: `callCC`, обработчики, `resume`) — то есть новый интерпретатор;
  отдельная задача, не блокирует язык и stdlib.
- **P1-4. Явное применение типов (`with`)** не работает нигде: `With` требует
  `TForall`, но `XVar` инстанцирует схему сразу, а лямбда `TForall` не
  производит, поэтому любое `with` даёт E0017. Слишком долго и сложно чинить
  сейчас.
  ```
  funct loop[T] (x T) : T = x
  sayn (loop with [Int] 5)      // E0017
  sayn (f with [`Int] 5)        // E0017
  ```
  Сопутствующее: возвращаемый тип с голой типовой переменной требует скобок
  (`: `A`), higher-rank параметр объявить можно, применить нельзя.

## Отклонено

- **P1-7. `let` как выражение.** Не ошибка. `let` остаётся как есть: `let`
  связывает одно имя, тело `in` при необходимости берётся в скобки.

## Проверено и закрыто

- [x] **P1-1, P1-2 (частично). `Numbers`, `Strings`, `Booleans`.** Каждое имя
      stdlib живёт в `Builtins.builtins` (один список на 73 имени), получает
      схему в `Scope.globalScope` и нативное замыкание в
      `IntInterpreter.buildInitialEnv`; обе стороны сверяются со списком при
      старте. Записи `Numbers`/`Strings`/`Booleans` — вид на те же адреса, что и
      плоские имена, поэтому `Numbers@+` и `+` не могут разойтись. `ShortCircuit`
      для `||`/`&&`/`and` не форсирует второй аргумент, если первый решает.
      `/` называет `Error` в ряду; `Error` — единственный встроенный эффект,
      доступный без объявления (живёт во внешнем скоупе, поэтому программа
      может объявить свой `Error`, как `app/std.marr`): у него есть нижний
      обработчик, превращающий непойманную ошибку в E0020. `%.`/`%` объявлены
      чистыми, нулевой делитель там — E0020. `sub` — начало, длина; `split ""`
      даёт `[s]`; `replace ""` возвращает исходную строку. Проверено:
      `stdlib.marr`; 5 тестов в describe «the standard library»; 360 примеров
      зелёные.
      Осталось в P1-1/P1-2: `Functions` (нужны полиморфные поля записи),
      `Arrays`, `Pairs`, `Output`, `Input`, `Conv`, `Env`, `File`, `System`.
- [x] **Лексер: оператор — это имя.** `|` больше не отдельный токен в `token`,
      а часть `nameText`: имя, начинающееся с операторного символа, состоит
      только из операторных символов, поэтому `||`, `|>`, `<|` — имена, а `|val`
      — пайп и `val`. Одиночный `|` `name` отображает обратно в `TPipe`, чтобы
      обновление записи и хвост ряда не сломались. `_` убран из продолжений
      имени: `_x` — это wildcard и `x`, а `or_else` остаётся одним именем.
      `kw` проверяет непродолжение по `wordChar`, а не по `normalChar`.
      Проверено: 4 теста в describe «the lexer» (`test/ParserSpec.hs`).
- [x] **P0-2. Память.** Куча переехала в Haskell-кучу: `Address` и `EnvId`
      теперь содержат `IORef`, ячейки создаются `freshCell`, читаются
      `readCell`, перезаписываются `writeCell`; таблиц `sHeap`/`sEnvs`/`sCode`
      больше нет. Трассирующий mark-and-sweep над интерпретатором был бы
      unsound: интерпретатор CPS на `callCC`, корни живут в Haskell-замыканиях
      и кадрах стека, и ручной сборщик не увидел бы их. Сборщик GHC видит, а
      значит собирает циклы (запись, окружение которой ссылается на себя) и
      сохраняет всё, на что ссылается захваченное продолжение. Код замыкания
      переехал в само замыкание (`VClosure EnvId (Maybe (IntMap Address))
      (Maybe Code) (Address -> Interp Address)`), поэтому мёртвая частичная
      аппликация уносит свой код.
      Проверено: `loop 2000000 0` проходит (раньше — `VirtualAlloc MEM_COMMIT
      failed`), таблица мемоизации не течёт (одна запись вместо растущей),
      `long_loop.marr` печатает 30000, 0, 300000; 3 теста в describe «memory».
      Оговорка: живая память всё ещё растёт с числом хвостовых вызовов — это
      остаток CPS-кадра, а не кучи; трамплин — в бэклоге.
- [x] **P0-4. `Nothing` — нижний тип.** Пустой литерал — `[Nothing]`, и
      `unifyTypes` знала это только слева, поэтому `sayn [[1], []]` падал с
      E0003, а `sayn [[], [1]]` работал. Теперь три механизма по позициям:
      `subsumesType` принимает `Nothing` как факт (это подтипизация, а не
      равенство), `joinTypes` сводит типы компонент массива и ветвей `if`
      (нижний тип не мешает, ряды объединяются), а `unifyTypes` сохраняет
      одностороннее `(TNothing, _)`, чтобы `var xs = []; xs := [1]`
      расширял тип. `f 1` при параметре `Nothing` по-прежнему отвергается.
      Проверено: `empty_arrays.marr`; 8 тестов в `UnifySpec`, 2 в
      `ExamplesSpec`.
- [x] **P0-1. `#{ base | ... }` — обновление, а не расширение.** Поля base не
      попадали ни в тип, ни в значение. Теперь `inferRecord (Just anchor)`
      добавляет унаследованные поля как `TEPropAccess anchor n`, так что
      интерпретатор не менялся: результат содержит все поля base, перечисленные
      заменены, base не затронут, мутабельность менять нельзя. Проверено:
      `record_update.marr`; 4 теста.
- [x] **P0-3. Встроенные функции нестрогие.** `and` форсировала оба аргумента,
      поэтому `and false (ieq (spin 1) 0)` не завершался. Теперь второй
      аргумент форсируется только при `true`. Остальные нативные операции
      форсируют ровно то, что нужно для результата. Проверено: `lazy_and.marr`;
      3 теста (оба случая `and` и ленивость `if`).
- [x] **P0-5. Операция эффекта видна там, где объявлен `effect`.** Раньше
      операции связывались только `under` и обработчиками, поэтому
      `funct twice () : {Doubt} Int = + (ask 1) (ask 2)` давал E0007, а
      `Doubt` в позиции ряда — «Unknown row alias». Теперь операции живут в
      `Scope.effects` и находятся через `findOperations` (только если имя не
      занято значением), вызов засчитывает эффект в ряд, `EffDef` хранит
      параметры как `Taste` (подстановка по тождеству, а не по имени),
      `RowEnv` помнит имена эффектов и отвечает на голый `Doubt` в позиции
      ряда подсказкой «write `{Doubt}`». Проверено: `effect_in_function.marr`
      печатает 3; функция без `Doubt` в ряду отвергается; `row D = {Doubt}` с
      `{...D}` работает; `test/ExamplesSpec.hs` — 4 примера.
- [x] `sayn [1, 2, 3]` печатал адреса элементов — `Stringify` для `VArray`
      вызывал `pretty` на адресах.
- [x] `let (a, (b, c)) = p` падал с «expects a pair, but the value is an
      unevaluated expression»; вложенные компоненты пары и записи форсируются
      только тогда, когда паттерн их разбирает.
- [x] `let` форсирует правую часть только для деструктурирующих паттернов;
      `let (a, b) = (spin 1, 2) in b` печатает 2, не форсируя `spin`.
- [x] `handle_while.marr` — работающий `while`: обработчик приводит тело
      `under` к WHNF, `break` возвращает результат.
