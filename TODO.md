# TODO: чего интерпретатор Mårran пока не умеет

Состояние на 2026-11-14, ветка `0.2-beta`, `stack test`: 319 примеров, 0
падений. Каждый пункт ниже — не план, а проверенный запуском факт: рядом стоит
программа, которая ведёт себя так, как описано. Если пункт закрыт, он
вычёркнут и остаётся в файле, чтобы было видно, что уже проверено.

Порядок: P0 — молча неверное поведение или то, что блокирует саму линию 0.2
(эффекты); P1 — отсутствующие конструкции языка; P2 — интерпретатор,
инструменты, тесты.

## P0 — корректность

### P0-1. Расширение записи `#{ base | ... }` молча теряет поля base

Синтаксис разбирается, типизируется и выполняется, но поля base в результат не
попадают — ни в тип, ни в значение.

```
val base = #{ val a = 1; val b = 2 };
val s = #{ base | val c = 3 };
sayn s          // #{val c = 3}
sayn s@a        // E0015: this record has no field `a`
```

Причина: `inferRecord` для `Just anchor` складывает только новые поля
(`accProps`), а интерпретатор (`TERecord _ ps _`) игнорирует anchor и строит
окружение только из `ps`. Тип и значение согласованы друг с другом, поэтому
ошибки нет — просто запись получается не та, что написана.

Готово, когда: либо `#{ base | ... }` действительно наследует поля base (в
типе, в `@` и в печати), либо конструкция отвергается диагностикой.

### P0-2. Память не освобождается: рекурсия падает на куче

`sHeap :: IntMap Value` только растёт, сборки мусора нет, хвостовые вызовы не
оптимизируются. 100 000 итераций хвостового цикла — 4.6 ГБ аллокаций, 217 МиБ
максимальной резидентной памяти и 497 МиБ всего; на Windows это упирается в
`VirtualAlloc`.

```
funct loop (i Int) (acc Int) : Int =
  if ieq i 0 then acc else loop (- i 1) (+ acc 1)
// loop 1000000 0 -> ok; loop 2000000 0 -> getMBlocks: VirtualAlloc MEM_COMMIT failed
// sum 600000 -> ok; sum 1000000 (не хвостовая) -> то же падение через ~18 c
```

Сообщение об ошибке — из RTS GHC, без спана и кода `E____`.

Готово, когда: живая память не растёт с числом итераций (сборка недостижимых
ячеек или подсчёт ссылок), а исчерпание памяти сообщается диагностикой.

### P0-3. `and` форсирует второй аргумент, хотя язык нестрогий

`if` ленив (`if true then sayn 1 else spin ()` печатает 1), а `and` — нет:

```
funct spin (n Int) : Int = spin n
sayn (and false (ieq (spin 1) 0))   // не завершается
```

`and` реализован как встроенное замыкание, которое сразу делает `getBool addrB`.
В языке с нестрогим вычислением `and false x` не должен трогать `x`.

Готово, когда: `and` ленив во втором аргументе (или встроенные булевы операции
описаны как строгие явно, с тестом).

### P0-4. `TNothing` унифицируется только слева: `[[], [1]]` проходит, `[[1], []]` нет

Пустой массив типизируется как `[Nothing]`, а в `unifyTypes` ветка
`(TNothing, _) -> pure scope` срабатывает, только когда `Nothing` слева.

```
sayn [[], [1]]   // [[1], []]  — ok
sayn [[1], []]   // E0003: cannot unify the type `Int` with the type `Nothing`
```

Обратная сторона того же: параметр, аннотированный `Nothing`, не принимает
ничего (`funct f (x Nothing) : Nothing = x; f 1` — E0003), потому что при
вызове `Nothing` оказывается справа.

Готово, когда: тип пустого массива — обычная метапеременная (или `Nothing`
унифицируется симметрично), и порядок элементов в литерале не влияет на
типизацию.

### P0-5. Операция эффекта видна только внутри `under ... to ... handle`

Объявление `effect` регистрирует операции в области видимости обработчика, а не
в глобальной, поэтому функция, которая должна выполнять эффект, его не видит и
не может объявить ряд:

```
effect Doubt
  ask : Int -> Int
end

funct twice () : {Doubt} Int = + (ask 1) (ask 2)   // E0007: `ask` is not in scope
funct twice () : Doubt Int   = + (ask 1) (ask 2)   // Unknown row alias: Doubt
funct twice () : {...Doubt} Int = ...              // Unknown row alias: Doubt
```

Работает только тело самого `under`:

```
sayn (under Doubt to ask 1 handle | ask x => resume x | then s => s)   // 1
```

То есть эффект нельзя вынести в функцию — а вся линия 0.2 про эффекты. Пока
это так, `row`-алиасы над эффектами (`row D = {...Doubt}`) тоже не работают:
`Unknown row alias`.

Готово, когда: операция эффекта видна в области видимости там, где объявлен
`effect`, и функция может назвать его ряд (`{Doubt}`, `Doubt`, `{...Doubt}` —
единообразно), а `under` только снимает обработчик.

## P1 — язык

### P1-1. Арифметика: только `+`, `-` и `Int`

Встроены `+`, `-`, `ieq`, `>`, `<`, `and`, `not`, `pred`. Нет `*`, `/`, `%`,
`rem`, `<=`, `>=`, `!=`, `or`.

```
sayn (* 6 3)          // E0007: `*` is not in scope
sayn (+ 1.5 2.5)      // E0003: cannot unify `Float` with `Int`
sayn (+ 'a' 'b')      // E0003: cannot unify `String` with `Int`; `++` не встроен
sayn (ieq 'a' 'a')    // E0003: cannot unify `String` with `Int`
```

`Float` существует как литерал и печатается, но над ним нет ни одной операции;
строки нельзя ни сравнить, ни склеить.

### P1-2. Массивы: литерал и печать есть, больше ничего

Нет индексации, `length`, `map`, `filter`, нет паттерна `[a, b]`, нет
`#[...]` (лексер знает `TSharpSquareL`, грамматика — нет).

```
val xs = [1, 2, 3];
sayn (xs 0)        // E0017: `xs` has type `[Int]`, which is not a function
sayn (length xs)   // E0007: `length` is not in scope
let [a, b] = xs    // E0013: unexpected `[`
sayn #[1, 2]       // E0013: unexpected `#[`
```

### P1-3. Записи: нет присваивания полю, нет `r.a`, нет подтипизации в паттерне

```
var r = #{ var a = 1 };
r@a := 2;          // E0013: unexpected `:=` (assign разбирает только имя)
r.a := 2;          // E0007: `r.a` is not in scope
sayn r.a           // E0007
```

Доступ к полю — только через `@`, и вложенный работает лишь со скобками:
`(r@a)@b` или `r@a@b`. Паттерн записи требует ровно те же поля:

```
val r = #{ val a = 1; val b = 2 };
let #{ val a } = r in sayn a   // E0003: cannot unify `#{a}` with `#{a; b}`
```

### P1-4. Явное применение типов (`with`) не работает нигде

`With` требует, чтобы тип выражения был `TForall`, но `XVar` инстанцирует схему
сразу, а лямбда `TForall` не производит — поэтому любое `with` даёт E0017.

```
funct loop[T] (x T) : T = x
sayn (loop with [Int] 5)      // E0017: `with` needs a polymorphic expression,
                              // but this one has the type ``m38 -> {} `m38`
val f = {(x) = x};
sayn (f with [`Int] 5)        // тоже E0017
```

Сопутствующее: возвращаемый тип с голой типовой переменной требует скобок —
`funct idA (x `A) : `A = x` это E0013 на `=`, а `: (`A)` работает.
Higher-rank параметр объявить можно, применить нельзя:

```
funct apply (f forall [A] ==> (A -> A)) (x Int) : Int = f x
sayn (apply {(n) = n} 5)      // E0003: cannot unify `forall [A]{} ==> `A -> {} `A`
                              // with ``m31 -> { | `m33} `m32`
```

### P1-5. Нет `match`, алгебраических типов и аннотаций выражений

`match` — ключевое слово в лексере без грамматики; `type` умеет только
синонимы, суммы типов не разбираются; аннотации `(e : T)` нет.

```
type Colour = Red | Green                 // E0013: unexpected `|`
sayn (match 1 with | 1 => 'one')          // E0013
sayn (5 : Int)                            // E0013
```

### P1-6. Нет модулей и `import`

```
import std      // E0013: unexpected `import`
```

`app/std.marr`, `app/modules.marr`, `app/main_el.marr`, `app/main_ic.marr` не
разбираются; `app/guess.marr` и `app/main.marr` типизируются, но `--run` их не
находит (см. P2-3).

### P1-7. `let` — только выражение, и блок после `in` ограничен

```
let x = 1;                 // E0013: unexpected `;`
let a = 1; b = 2 in ...    // E0013: unexpected `;`
let x = 1 in
  val y = 2;               // E0013: unexpected `val` (нужны скобки)
  sayn y
```

Локальных `funct` нет (`E0013`), `if` без `else` нет (`E0013`).

## P2 — интерпретатор и инструменты

### P2-1. Трассировка и strict-режим объявлены, но не включаются

`MARRAN_TRACE` описан в комментарии к `traceEval`, но `sTrace` инициализируется
`False` и нигде не читает переменную окружения — трассировка молча выключена.
`sNoMemo` существует, но тоже ничем не включается: strict-режима нет.

### P2-2. Печать значений

Функции печатаются адресом (`!closure[&00000001]!`), thunk-ы — `!vthunk: ...!`,
`trace` показывает thunk, а не значение. Печать массивов уже исправлена
(раньше печатались адреса элементов).

### P2-3. `--run` и аргументы программы

`--run` принимает только имя в `app/marr` (без пути и расширения), лишние
аргументы уводят в usage, `args` всегда `[]`:

```
marran-exe --run guess          // program not found: guess.marr
marran-exe --run scoping extra  // usage: ...
```

### P2-4. Нативные лямбды не реализованы

`TENLambda` в интерпретаторе — `rtError "native lambdas are not implemented"`.

### P2-5. `read_string` требует кавычек

`read_string` парсит строку как литерал Mårran, поэтому `hello` — ошибка, а
`'hello'` — нет. Для интерактивных программ это неожиданно.

### P2-6. Предупреждения сборки

`stack build` даёт 30 `-Wunused-top-binds`, 9 `-Wunused-imports`, 3
`-Wduplicate-exports`, по одному `-Wunused-matches`, `-Wunused-local-binds`,
`-Wmissing-signatures`, `-Wtype-defaults`. Это не регрессии, но шум, за которым
не видно новых.

### P2-7. `hpack` недоступен

`Marran.cabal` правится вручную вместе с `package.yaml`; расхождение может
накопиться. Либо поставить `hpack` и генерировать cabal, либо зафиксировать это
в README.

## Проверено и закрыто

- [x] `sayn [1, 2, 3]` печатал адреса элементов — `Stringify` для `VArray`
      вызывал `pretty` на адресах.
- [x] `let (a, (b, c)) = p` падал с «expects a pair, but the value is an
      unevaluated expression»; вложенные компоненты пары и записи форсируются
      только тогда, когда паттерн их разбирает.
- [x] `let` форсирует правую часть только для деструктурирующих паттернов;
      `let (a, b) = (spin 1, 2) in b` печатает 2, не форсируя `spin`.
- [x] `handle_while.marr` — работающий `while`: обработчик приводит тело
      `under` к WHNF, `break` возвращает результат.
