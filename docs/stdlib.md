# Нативная стандартная библиотека

Нативная библиотека — это не файл на Mårran, а набор **нативных модулей**,
которые ввозятся через `import`. До импорта ни одного нативного имени не
видно: `+`, `say`, `map` — такие же имена из модуля, как и объявленные в
файле, и без `import` проверка типов ответит `E0007`.

```
module Main
import @native Numbers
import @native Output

funct main () : {Output} () =
  sayn (+ 1 2)
```

`import @native` без имени модуля ввозит весь нативный скоуп сразу. Так
пишутся преамбулы тестов и небольшие программы; в остальном лучше называть
модули поимённо, потому что это и есть интерфейс файла.

Список ниже — единственный источник истины: его проверяет `BuiltinSpec`,
сверяя с `Builtins.builtins`. Имя, добавленное в интерпретатор и забытое в
таблице типов (или наоборот), — ошибка сборки, а не сюрприз для читателя.

## Значения

### `Numbers`

Целые: `pred`, `+`, `-`, `*`, `/`, `%`, `neg`, `abs`, `max`, `min`,
`ieq`, `ineq`, `>`, `<`, `<=`, `>=`.
Вещественные: `+.`, `-.`, `*.`, `/.`, `%.`, `fneg`, `fabs`, `fmax`, `fmin`,
`feq`, `fneq`, `<.`, `>.`, `<=.`, `>=.`.
Преобразования: `to_int`, `to_float`.

`/` и `%.` называют `Error` в своём ряду: нулевой делитель — это ошибка,
которую можно поймать обработчиком, а не падение интерпретатора. `%` —
остаток целых, он объявлен чистым, поэтому нулевой делитель у него —
`E0020`.

### `Strings`

`++`, `slen`, `sub`, `split`, `join`, `trim`, `upper`, `lower`, `contains`,
`replace`, `seq`, `sneq`.

`sub` берёт начало, длину и строку; срез за концами строки обрезается, а не
падает. `seq` и `sneq` — сравнение строк; `==` из `Conv` сравнивает
структурно и работает для строк тоже.

### `Booleans`

`not`, `||`, `&&`, `^`, `nor`, `nand`, `and`.

`||`, `&&` и `and` ленивы во втором аргументе: `and false x` не трогает `x`.

### `Functions`

`id`, `const`, `flip`, `compose`, `apply`, `curry`, `uncurry`.

Все они полиморфны, включая ряд эффектов аргумента: `apply` применяет
функцию и платит ровно тот ряд, который та объявляет.

### `Arrays`

`head`, `tail`, `empty`, `alen`, `map`, `filter`, `any`, `all`, `foldl`,
`foldr`, `concat`, `zip`, `at`, `take`, `drop`.

`head` и `tail` пустого массива — `E0020` (они объявлены чистыми). `at` за
границами — эффект `Error`, поэтому его можно поймать `try` или `under
Error`.

### `Pairs`

`fst`, `snd`.

### `Conv`

`show`, `parse`, `==`, `===`, `!=`, `!==`.

`==` сравнивает содержимое, `===` — сами значения: `1 === 1` ложно, потому
что две единицы — два значения. `show` превращает значение в текст;
`say`/`sayn` пользуются им же.

`parse` читает значение из текста и требует `with`: `parse with [Int] '42'`
даёт `42`, а `parse '42'` — ошибка, потому что без типа нечего строить.
Поддерживаются `Int`, `Float`, `Boolean`, `String`, `()`, массивы, пары,
записи и энумы; функция и любой незнакомый тип отвергаются ещё проверкой
типов, а поле энума проверяется тогда, когда текст называет конструктор.
Текст пишется как литерал значения:
`[1, 2]`, `(1, "one")`, `#{x = 1; y = 2}`, `Some 5`. На верхнем уровне
`String` — это сам текст, поэтому `parse with [String] 'hello'` возвращает
`'hello'`; внутри агрегата строка в кавычках. Неразобранный текст и
отсутствующее поле записи поднимают `Error` (`E0020`).

Переменная типа во время выполнения неизвестна: `parse with [a] s` внутри
`funct f[a]` — это ошибка `E0020`, а не молчаливое значение.

### `Memory`

`force`, `whnf`. `force` доводит отложенное вычисление до значения, `whnf` —
до слабой головной нормальной формы.

### `Error`

`assert`, `try`. `assert условие 'сообщение'` ничего не делает, если условие
истинно, и поднимает `error` иначе. `try тело on_error` выполняет тело под
обработчиком `Error`: сообщение уходит в `on_error`, нормальное завершение
возвращает значение как есть.

## Эффекты

Эффект и его операции приезжают одним модулем: `import @native Output`
приносит и имя эффекта `Output` для ряда, и операции `say`, `sayn`, `trace`.

| Модуль | Операции | Что делает |
|--------|----------|------------|
| `Output` | `say`, `sayn`, `trace` | печать; `trace` показывает значение и возвращает его |
| `Input` | `read_string`, `read_int`, `read_float`, `read_boolean` | чтение строки ввода |
| `Random` | `random_int`, `random_float`, `random_boolean`, `random_string` | случайные значения |
| `Time` | `time_ms`, `sleep` | время и пауза |
| `Env` | `get_env`, `set_env` | переменные окружения |
| `File` | `read_file`, `write_file`, `append_file`, `file_exists`, `delete_file`, `list_directory` | файлы; операции, которые могут не сработать, называют ещё и `Error` |
| `System` | `args`, `hostname`, `system`, `exit` | аргументы командной строки, хост, внешняя команда, выход |
| `Error` | `error` | отказ программы; его ловит `under Error` или `try` |

`Error` — единственный эффект, который существует без объявления: у
интерпретатора есть нижний обработчик, превращающий непойманный `error` в
диагностику `E0020`. Объявить собственный `effect Error` всё равно можно —
объявление перекрывает встроенное.

## Как это устроено

- `src/Builtins.hs` — список всех имён и модулей. Это единственная таблица;
  `Scope` (типы) и `IntInterpreter` (значения) сверяются с ней при старте.
- `Scope.nativeScope` собирает скоуп из имён тех модулей, которые файл
  импортировал. Нативные значения интерпретатора лежат в корневом окружении
  ниже окружения программы, поэтому имя, которое не импортировали, просто не
  попадает в скоуп проверки типов.
- Записи библиотеки (`Numbers@+`, `Strings@slen`) удалены: у модуля нет
  полиморфного поля, поэтому все имена плоские.
